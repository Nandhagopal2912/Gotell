How to read this dashboard
up
The latest check got a healthy answer (a 2xx status).
failing
The latest check failed, but not 3 times in a row yet. Gotell waits for 3 so a single blip doesn't raise an alarm.
down
3 or more checks failed in a row: an incident is open until the next healthy check.
paused
Maintenance: checks are stopped, and this time never counts against uptime.
Uptime
Healthy checks ÷ checks that said up or down. Checks Gotell itself cancelled don't count either way. No data shows as n/a, never as a made-up 100%.
Recovered
A check that failed first, then succeeded on a retry. It counts as up, but is shown separately: often a sign the app was waking from sleep (a suspected cold start).
p50 / p95
Time to first byte. p50 is the typical wait (half the checks were faster); p95 is the bad-but-normal wait (1 in 20 was slower). Averages hide both, so Gotell shows these instead.
Missing
Checks that should have happened while Gotell was running, but have no result.
Gotell off
Time when Gotell itself wasn't running. It's a gap in monitoring, never counted as the target being down.
“–”
Not measured (for example, a reused connection has no new DNS lookup). Never shown as 0 ms.
